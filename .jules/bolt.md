## 2024-05-16 - [Real-time Audio Processing Memory Allocations]
**Learning:** Using `Array.from` on a Uint8Array when passing chunks to `String.fromCharCode.apply` inside a high-frequency `onaudioprocess` handler creates massive GC pressure by constantly allocating and discarding 32KB intermediate JS arrays. `String.fromCharCode.apply` natively supports TypedArrays in modern engines, rendering `Array.from` unnecessary. Additionally, `filter` on arrays used to manage frequently starting/stopping audio nodes (like `sourceNodesRef`) incurs O(N) array re-allocations on every node completion, which is inefficient.
**Action:** Always use a `Set` for managing dynamic collections of active, ephemeral objects (like AudioBufferSourceNodes) that require frequent additions and removals. For performance-critical code paths, pass TypedArrays directly to functions like `String.fromCharCode.apply` (casting as `unknown as number[]` for TS) to prevent unnecessary heap allocations and GC spikes.
